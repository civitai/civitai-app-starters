Write subagents, off unless the page opts in. `subagents.write` (`{ tools, instructions?, files?, commands? }`) lets `dispatch_agent` take `mode: "write"`: a subagent that may use any tool in `write.tools` (a free-form command tool included; never `dispatch_agent`, `ask_choice`, `open_panel` or `update_panel`), with write rules in its system prompt and `write.instructions` after them. Its result adds `mode: 'write'`, `changed: { path, op }[]` (built only from the successful results of the tools named in `files`, never from the subagent's words) and `ranCommands` (calls to the `commands` tools that ran; what they changed is not in `changed`). Its calls reach `beforeToolCall` and `tool-result` with `subagent` set, like a read subagent's. A write subagent saves its progress with the reply's, so one interrupted by a closed page comes back on Continue as `status: 'interrupted'` with the `changed` list saved so far, and is never run again. Its card says "Subagent · edits" with files changed and commands run. Concurrent write subagents are not kept apart (no path scopes or locks): two may edit the same file. Stop stops every subagent; there is no per-subagent Stop. Without `write`, `mode: "write"` is refused as before, and read subagents are unchanged.
