**`<civitai-chat>` keeps a message it cannot send yet, shown at once, and sends it when it can.** A message sent while the page's `holdReason` is set or an added MCP server lists its tools now waits, shown at once as the viewer's bubble marked with what it waits for, and goes by itself when the hold lifts (before, it was left in the message box and the Send button was off). A page can keep a message back the same way: `before-send`'s detail gains `queue(waiting)`, which returns a `QueuedMessage` with `release()` and `cancel()`, and `queued: true` on the `before-send` that fires as a waiting message goes. The waiting bubble has Edit and Cancel; one waits at a time, and the chat holds meanwhile. A waiting message that will not go (the page cancels it, `queueTimeoutMs` runs out, default `QUEUE_TIMEOUT_MS` = 3 minutes, or another chat, app or sign-out takes its place) comes back into an empty message box, or, when the viewer typed there or is dictating, as a "This message was not sent" notice with Put it back. New: `chat.queuedMessage`, the `queue-change` event (`QueueChangeDetail`), `queueTimeoutMs`. See "A message that waits" in the README.
