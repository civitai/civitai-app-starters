**`<civitai-chat>` says when a message can go: a read-only `canSend` property and a `can-send-change` event.** `canSend` is `true` when `send(text)` would send now: the chat has started, no reply is running, and nothing holds it (the page's `holdReason`, a saved chat the viewer is opening, a message still on its way, the chat starting again for a new `app` or `backend`, or an added MCP server still listing its tools). Each of these is shown in the message box, which keeps what is sent meanwhile, so a message sent while a saved chat opens no longer goes into the chat being left. On Civitai's own conversation store, as already on a host `backend`'s, an open that finishes after a later open or a new chat is now dropped: the last chat picked is the one that ends open, a chat whose open never answers no longer holds up the next pick, and New chat no longer waits for (and is no longer replaced by) a chat still loading. The Buzz permission request is now asked with a `signal`: a viewer who closes it without answering counts as not having agreed after two minutes, instead of leaving the chat waiting. `can-send-change` fires with `{ canSend }` (type `CanSendChangeDetail`; it bubbles and is composed) once each time that changes, so a page holding a message of its own can send it the moment the chat can take it instead of calling `send()` again on a timer. See "When a message can go" in the README.
