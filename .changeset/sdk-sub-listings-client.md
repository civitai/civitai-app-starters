Add `app.subListings`, a typed client for the App Store sub-listing routes (`/api/v1/blocks/sub-listings/{upsert,withdraw,mine}`), so an app no longer hand-rolls `app.site.post('blocks/sub-listings/upsert', …)`. `upsert(input)` sends only the six fields the server's strict body accepts (`itemKey`, `title`, `subPath`, `tagline`, `imageId`, `contentRating`) and leaves out an optional that is `null` or `undefined`; `withdraw(itemKey)` resolves `{ ok, withdrawn }`; `mine()` resolves `{ items }` with `updatedAt` revived as a `Date`. A refusal carrying a `code` rejects as the new `SubListingError`, an `ApiError` subclass whose `code` is typed as `SubListingErrorCode`; a refusal without one stays a plain `ApiError`, and a malformed reply rejects with a `CivitaiError`. New exports: `SubListingError` and the types `SubListingsClient`, `SubListingUpsertInput`, `SubListingUpsertResult`, `SubListingWithdrawResult`, `MySubListing`, `SubListingStatus`, `SubListingContentRating`, `SubListingErrorCode`, `SubListingCallOptions`. No scope or manifest change: the routes still need `apps:store:items:write`, which is never minted for dev-token, dev-tunnel or review sessions.
